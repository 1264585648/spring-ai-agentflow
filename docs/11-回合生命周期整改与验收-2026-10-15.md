## 修复后的行为

### 任务被接收后，才能切换回合

`SseAgentEventSink` 的构造函数不再注册活动回合。流水线把 `activate` / `release` 回调交给 `TurnTaskSupervisor`，在准入及 worker 接收成功后，由统一生命周期临界区登记 Run、切换事件归属、取消旧 Run。

准入满或 executor 拒绝新任务时，旧任务不被取消，旧回合的 SSE 归属不被抢占。即使 worker 立即启动，也要等待激活提交后才能进入业务代码。同步 Executor 的业务逻辑在生命周期锁外运行，避免把网络 I/O 带入全局锁。

这里的临界区只包含短时内存操作；宿主提供的 Executor 必须及时接收或明确拒绝，不能在 execute 中无限阻塞。外部适配器仍须设置自己的超时，Java 中断不保证强制停止所有第三方 I/O。

### 前端关闭与迟到回执

回合状态集中在 `frontend/src/hooks/useChatSession.ts`。关闭或传输中断时，明确结束本地活动回合，保留历史消息，清理生成标记和进度，并按原始 turnId 发起取消。重新打开不再继承无法结束的生成状态。

每个提问请求持有自己的 LocalTurn。只有当前拥有者可以修改全局生成状态；旧请求的迟到异常或 turnId 重映射不能抢占新回合。已经收到 SSE done 的历史消息，不因迟到的 HTTP 异常改成失败。旧卡片的执行回执仍按 actionId 写回原消息，不清空新回合进度。

关闭时的取消请求可能早于 ask 被后端接收，所以迟到的受理回执到达后，会再次按原 turnId 尝试取消。这个动作不会针对当时的新回合。

### 报告测试

数据库诊断报告测试不再依赖已经移除的 `HikariCP` 产品名字，而是验证目标服务、连接池活跃/最大容量、等待线程数、慢查询会话及耗时、模拟来源与实际执行前核验提示。没有删掉整个测试或减少为只断言非空。

## 取消接口补充契约

这是对 [03｜前后端接口与 SSE 协议契约](03-前后端接口与SSE协议契约.md) 的回合取消补充。

```http
POST /api/v1/chat/cancel?sessionId=sess_A&turnId=turn_A
```

两项参数均为必填的 1～128 字符非空标识。缺失或无效返回 400，不回退到取消整个会话当前任务。

```json
{"code":200,"turnId":"turn_A","cancelled":false}
```

`cancelled=true` 表示匹配的活动 Run 已接受取消并发起中断；`false` 表示未取消该 Run，例如它已结束、不存在或当前已是另一个 turnId。HTTP 成功、本地界面停止、第三方 I/O 已停止是不同的状态，不能互相替代。

本接口不撤销已提交的写操作，也不是卡片“放弃”接口。仍沿用 `/api/v1` 的身份与权限校验。旧调用方需要补充原 turnId；内部连接断开事件使用的会话级取消不暴露为浏览器回退路径。
