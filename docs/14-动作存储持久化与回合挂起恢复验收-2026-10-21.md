## 核心设计与契约

### 1. 审批态与执行态分离及持久账本 (`sys_action_ledger`)

- **表结构唯一事实标准**：已同步写入 [sql/init_schema.sql](../sql/init_schema.sql) 第 7 节 `sys_action_ledger` 与第 8 节 `sys_turn_checkpoint`。
- **状态映射规则**：
  | `CardState` | `ApprovalState`（审批态） | `ExecutionState`（执行态） | 说明 |
  | :--- | :--- | :--- | :--- |
  | `ISSUED` | `PENDING` | `NOT_STARTED` | 提案已签发，等待人工确认 |
  | `SUBMITTING` | `APPROVED` | `EXECUTING` | 已通过 CAS 原子领取执行权，正在调用外部系统 |
  | `SUBMITTED` | `APPROVED` | `SUCCEEDED` | 外部执行成功（或对账恢复成功）并已落盘归档 |
  | `FAILED` | `APPROVED` | `FAILED` | 进入外部写操作前确定失败 |
  | `EXPIRED` | `EXPIRED` | `NOT_STARTED` | 超时未审批自动失效 |
  | `CANCELLED` | `CANCELLED` | `NOT_STARTED` | 用户主动放弃或关联回合已取消 |
  | `EXECUTION_UNKNOWN` | `APPROVED` | `EXECUTION_UNKNOWN` | 已触发执行但回执丢失/超时/落库前崩溃，待对账 |

### 2. 外部写成功、落库前崩溃的对账闭环 (`ActionGate.reconcile`)

```http
POST /api/v1/card/reconcile
Content-Type: application/json
```
```json
{
  "actionId": "act_9f8a32b14e9a",
  "sessionId": "sess_88921a9f-4310"
}
```
- 当提案处于 `SUBMITTING` 或 `EXECUTION_UNKNOWN` 时，调用 `CardSubmitHandler.reconcile(record)`，通过稳定 `idempotencyKey` 向外部端口（如 `OpsActionPort.findExecutedResult(key)`）核查；
- 若外部系统确已执行成功并返回有效 `ticketId`：账本原子收敛为 `SUBMITTED`（`ApprovalState.APPROVED` + `ExecutionState.SUCCEEDED`），并驱动关联 `TurnCheckpoint` 恢复为 `COMPLETED`，**全程不二次调用 `handleSubmit`**；
- 若外部系统未返回确定回执：保持 `EXECUTION_UNKNOWN` 并返回 500 `EXECUTION_UNKNOWN`，转人工核查，严禁盲目重做。

### 3. 回合挂起检查点与工具版本一致性

- **挂起释放槽位**：`AgentPipelineServiceImpl` 在下发待确认卡片后自动调用 `TurnCheckpointStore.saveWaitingApproval(...)` 保存检查点（含 `turnId`、`pendingActionId`、`expectedIssuanceId`、`expectedToolVersion`、已完成 `StepResult` 列表），随即结束当前工作线程并释放 `TurnTaskSupervisor` 会话槽位，等待期间不阻塞会话邮箱。
- **取消联动**：等待审批期间调用 `/api/v1/chat/cancel?sessionId=...&turnId=...` 时，`AgentPipelineServiceImpl.cancelActiveTurn` 联动将挂起检查点与关联待确认卡片同步流转为 `CANCELLED`，阻止后续迟到审批执行。
- **工具版本锁定**：卡片签发与检查点均锁定 `toolVersion`（默认 `"v1"`）。等待确认期间若 `CardSubmitHandler.toolVersion()` 发生变更，`ActionGate.submit` 立即抛出 `CardStateConflictException`（HTTP 409），拒绝隐式切换实现。
