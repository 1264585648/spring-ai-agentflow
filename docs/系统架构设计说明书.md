# 系统架构设计说明书：催收域智能答疑机器人

## 1. 建设背景与系统目标

在催收业务场景中，坐席与催收员面临高频的业务规范咨询、客户抗辩应对、利息与罚息减免试算、停催报备及系统操作等问题。传统模式下依赖人工组长答疑或分散在各处的静态文档，存在响应慢、口径不一致、合规风险高的问题。

本系统旨在打造一个高可用、高合规、具备自我进化能力的**催收域智能答疑机器人**，核心支撑以下两项关键业务诉求：
1. **重复问题自动归档 SOP**：沉淀催收员的日常提问，自动识别高频、重复或未解决问题，提炼形成标准作业程序（SOP）并闭环回流至知识库。
2. **推荐解决方案并闭环 BPM 提单（Human-in-the-loop）**：针对涉及实质业务变更（如停催、息费减免、客诉升级）的咨询，Agent 给出政策试算与推荐方案，通过可视化交互卡片供催收员二次核验与微调，一键打通企业 BPM 系统发起正式审批工单。

## 3. 核心流水线与意图识别（串行降级设计）

在催收场景中，高频问题追求毫秒级响应，复杂问题要求高准确率与严格合规。系统采用 L1 $\rightarrow$ L2 $\rightarrow$ L3 串行降级策略：

| 匹配层级 | 技术选型与实现 | 响应耗时 | 覆盖场景 | 降级机制 |
| :--- | :--- | :--- | :--- | :--- |
| **L1 规则匹配** | 前缀字典树 (Trie)、正则表达式、精确关键词匹配表 | `< 30ms` | 错误码直查（如 `DEDUCT_504` 银行限额）、固定话术指令、工单单号直查 | 未命中时下沉到 L2 |
| **L2 向量检索** | Spring AI VectorStore + 专有 Embedding (如 text-embedding-v3 / DashScope) | `< 100ms` | 高频标准化催收问答、已有 SOP 库语义相似问（设定相似度阈值例如 0.86） | 未达到置信度阈值下沉到 L3 |
| **L3 LLM 兜底** | Spring AI ChatModel 结构化输出（JSON Schema） | `500~1200ms` | 复合复杂诉求（如债务人既要求停催又声称要投诉涉案）、口语化模糊表述改写 | 改写并判定意图后直接进入调度决策，不回流 L1 |

**调度决策分支**：
- **单意图 + 高置信度**：跳过 MasterAgent（Skip MasterAgent），直接路由给指定 SubAgent，大幅降低推理延迟与 Token 消耗。
- **多意图 / 低置信度**：进入 MasterAgent，通过子工具调度链拆解子任务并行或串行执行。

## 4. 核心功能一：重复问题自动归档 SOP（数据闭环体系）

### 4.1 业务流程设计
催收业务政策和突发客诉应对具有较强的时效性，通过“线上日志沉淀 $\rightarrow$ 离线聚类 $\rightarrow$ LLM 提炼 SOP $\rightarrow$ 人工审核 $\rightarrow$ 知识库更新”构建自进化闭环。

```mermaid
sequenceDiagram
    autonumber
    participant Agent as 催收员
    participant ChatSys as 智能答疑系统
    participant DB as 会话日志存储 (PostgreSQL / ES)
    participant ClusterJob as 定时聚类挖掘任务 (Cron)
    participant SOPAgent as SOP提炼智能体
    participant Expert as 催收知识库管理员
    participant KB as 生产知识库 (L1/L2)

    Agent->>ChatSys: 发起提问（如："客户出具虚假贫困证明怎么处理？"）
    ChatSys->>DB: 记录 Query、置信度、路由分支、是否触发转人工/提单
    
    rect rgb(240, 248, 255)
    Note over DB, KB: 定时离线挖掘与 SOP 生成流程 (每日/每周执行)
    ClusterJob->>DB: 提取周期内 L3 兜底、未命中或转工单的高频日志
    ClusterJob->>ClusterJob: 向量化 + HDBSCAN 文本聚类，形成聚类簇
    ClusterJob->>SOPAgent: 传入 Top N 聚类簇提问样本
    SOPAgent->>SOPAgent: 1. 概括标准问题与背景<br/>2. 提炼标准作业程序步骤 (Step-by-step)<br/>3. 生成扩展同义问法 (用于增强召回)
    SOPAgent->>Expert: 生成 SOP 待审草稿 (状态: DRAFT)
    Expert->>Expert: 审查合规要点，核准试算标准与表单规范
    Expert->>KB: 审核通过，正式发布
    end

    KB-->>ChatSys: 热加载规则词典 (L1) 与向量索引库 (L2)
```

## 5. 核心功能二：推荐解决方案与 BPM 工单协同（Human-in-the-loop）

### 5.1 交互流程设计
催收域涉及案件状态扭转与账务减免，必须严格实行 **“AI 测算方案 $\rightarrow$ 人工确权/微调 $\rightarrow$ 系统调用提单”** 的人机协同架构。

```mermaid
sequenceDiagram
    autonumber
    participant Front as 催收工作台 (前端)
    participant ChatService as 答疑后台 (ChatController)
    participant SubAgent as 减免与工单 Agent
    participant BPM as 企业 BPM 流程引擎

    Front->>ChatService: 提问: "案件 800921 客户声称丧失劳动能力，申请利息罚息全免"
    ChatService->>SubAgent: 调度至工单 Agent 执行
    SubAgent->>SubAgent: 1. 调用案件查询工具 (查本息、逾期天数、催记)<br/>2. 检索减免合规政策 (严重残疾/失能减免标准)<br/>3. 计算推荐减免额与提单类型
    
    SubAgent-->>Front: SSE 推送: 解释文本 + bpm_confirm_card 事件
    Note over Front: 前端挂载卡片组件，预填如下信息：<br/>• 案件号: 800921 (锁定)<br/>• 申请流程: 困难客户特殊减免<br/>• 推荐减免金额: 2340.50 元 (允许催收员微调)<br/>• 申请理由: 客户失能证明已核验，申请息费豁免

    Front->>Front: 催收员核查原件，确认/调整参数，点击【提交审批】
    Front->>ChatService: POST /api/v1/bpm/submit-ticket (携带 cardToken + 修改后表单)
    ChatService->>BPM: 调用 BPM OpenAPI 创建流程实例 (带幂等键)
    BPM-->>ChatService: 返回工单实例号 (如: BPM-20261008-0091)
    ChatService-->>Front: 回写确认消息: "工单创建成功！审批单号：BPM-20261008-0091，当前流转节点：组长复核"
```

## 6. 执行容器与安全合规 Hooks 链

催收业务受金融监管（如不得暴力催收、严格保护 PII 隐私）高度约束，SubAgent 执行容器内嵌串行 Hooks 过滤器链：

```mermaid
flowchart LR
    A["输入请求"] --> B["Pre-Hook 1: DataMaskingHook<br/>(PII敏感信息掩码: 身份证/卡号脱敏)"]
    B --> C["Pre-Hook 2: ProgressNotifierHook<br/>(通过SSE通知前端思考进度)"]
    C --> D["Agent 核心推理与工具调用<br/>(Tool / RAG / Prompt Execution)"]
    D --> E["Post-Hook 1: ComplianceGuardHook<br/>(合规红线词库过滤/违规恐吓话术熔断)"]
    E --> F["Post-Hook 2: SessionPersistenceHook<br/>(上下文持久化与审计留痕)"]
    F --> G["Post-Hook 3: CircuitBreakerHook<br/>(下游API延迟超限熔断降级)"]
    G --> H["输出 SSE 事件流"]
```

## 7. 技术栈选型

- **微服务核心**：Java 21 + Spring Boot 4.x
- **AI 编排框架**：Spring AI 2.x（ChatClient、Prompt Template、Tool Calling、VectorStore）
- **流式通信**：Spring MVC `SseEmitter` / WebFlux + EventSource
- **向量检索与存储**：PostgreSQL (pgvector) / Milvus / Elasticsearch 8.x
- **高速缓存与状态机**：Redis 7.x（存储多轮短期上下文、防重复提交 Token）
- **工单集成**：企业 BPM OpenAPI (REST / gRPC) + 幂等重试机制
