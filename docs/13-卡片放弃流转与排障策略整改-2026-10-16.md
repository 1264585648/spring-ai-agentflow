## 核心设计与契约

### 1. 卡片放弃生命周期流转（Card Abandonment）

#### 1.1 状态机流转守则
- 处于 `ISSUED` 状态的卡片允许被主动流转为 `CANCELLED`；
- 处于 `SUBMITTING`、`SUBMITTED`、`FAILED`、`EXECUTION_UNKNOWN` 或 `CANCELLED` 的卡片，严禁再次发起放弃（返回 409 Conflict）；
- 处于 `EXPIRED` 的卡片返回 400（已过期）；
- 放弃操作必须基于服务端签发的最新 `issuanceId` 进行原子版本 CAS 检查，彻底消除“用户点击放弃的同时又并发触发提交”的竞态漏洞。

#### 1.2 接口契约
对齐 [03-前后端接口与SSE协议契约](03-前后端接口与SSE协议契约.md) 3.6 节：
```http
POST /api/v1/card/cancel
Content-Type: application/json
```
```json
{
  "actionId": "act_9f8a32b14e9a",
  "sessionId": "sess_88921a9f-4310",
  "reason": "用户主动放弃处置"
}
```
响应：
```json
{
  "code": 200,
  "message": "提案已放弃",
  "actionId": "act_9f8a32b14e9a",
  "cardType": "TROUBLESHOOT_ACTION",
  "turnId": "turn_1760410000_a1b2c3",
  "state": "CANCELLED"
}
```

#### 1.3 前端交互状态收敛
- `frontend/src/components/InteractiveCard.tsx`：渲染“放弃”按钮（文本取自 `card.cancelButtonText || '放弃'`）；
- 点击放弃后，向后端发起请求；成功后卡片进入 `CANCELLED` 锁定态，隐藏操作按钮，置灰表单并提示“该处置提案已放弃，系统未执行任何变更”；
- 若已被放弃，前端强行阻断任何表单提交。

### 2. `attachedTools` 禁用语义（Strict Tool Disabling）

在 [AgentChatClientFactory.java](../src/main/java/com/example/springai/infra/client/AgentChatClientFactory.java) 中确立明确的三态判定规则：

| 数据库 `attachedTools` 取值 | 解析语义 | 运行期行为 |
| :--- | :--- | :--- |
| `null` | 未显式配置工具策略 | 兼容旧逻辑，按角色（如 `LOG_DIAGNOSE_AGENT`）继承默认安全只读工具 |
| `[]` 或空白列表 | **显式声明禁用所有工具** | **严格返回 0 个工具（`new Object[0]`）**，绝对不回退到默认角色工具 |
| `["logQueryTool", ...]` | 显式白名单工具 | 取白名单与容器候选安全工具的交集挂载 |

---

### 3. 排障处置建议策略化（Troubleshoot Policy Strategy）

在 [TroubleshootSubAgent.java](../src/main/java/com/example/springai/scenario/troubleshoot/TroubleshootSubAgent.java) 中，将原硬编码的卡片提案内容解耦为可计算的策略：

1. **临时连接池建议上限计算策略**：
   - 提取真实连接池水位：`activeConnections` 与 `maxPoolSize`；
   - 若未取得有效指标：降级为基线建议值 50，且必须标记为离线/演示估计；
   - 若取得有效指标：
     $$\text{suggested} = \min\left(500, \max\left(\lceil \text{maxPoolSize} \times 1.5 \rceil, \text{activeConnections} + 20\right)\right)$$
   - 确保建议值合理提升且严格受控在系统允许的安全极值 $[10, 500]$ 区间内。

2. **处置动作动态组装策略**：
   - 若仅连接池高负载、无阻塞慢查询：动作明确为 `临时扩容连接池至 {suggested} 容量`，不伪造不存在的 slow session；
   - 若存在明确慢查询会话（如 `slowQuerySessionId = trx_xxx`）：动作组装为 `Kill阻塞慢查询({sessionId})并临时扩容连接池`；
   - 若既无指标也无慢查询且为纯咨询问题：坚决不下发任何执行提案卡片（已在先前版本落地，保持守则）。
